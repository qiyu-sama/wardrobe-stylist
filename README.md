# wardrobe-stylist

一个「会下判断」的穿搭 Skill。装给 AI Agent 用，不是给你逛街看的清单。

核心立场只有一条：**穿搭问题缺的从来不是「这件好看吗」，而是「这套在我这个场合、这个衣柜、这具身体上，成立还是不成立」。**

所以它交付的不是建议清单，是判断——**先定这套属于哪个风格，再说好不好。**

---

## 它解决什么

大多数穿搭建议都在给「风格描述」：老钱是米白驼色、机能是黑色多口袋、复古是水洗丹宁。描述不能执行——你不会因为知道「老钱是米白」就穿对老钱。

这个仓库给的是另一层：**判据、硬禁忌、冲突仲裁、证据等级**。

一件衣服到底归哪个包、两件不同体系的单品能不能拼、这个场合到底允不允许穿这套——这些都有明确的顺序，不用每次重新吵一遍。

## 五个风格包

| ID | 包 | 一句话内核 | 失败长相 |
|---|---|---|---|
| `CM` | 商务正装 | 让对方感到被尊重 | 像借来的西装 |
| `OM` | 老钱 | 不用证明自己 | 显得「在解释自己」 |
| `DT` | 黑暗机能 | 每个变量都在跟环境较劲 | 像 cosplay |
| `AV` | 美式复古 | 能解释成「当年人这么干活」 | 显「假」 |
| `JM` | 日系极简 / City Boy | 松下来还有形状 | 显「没穿好」 |

每个包都是同一个十段结构：定位 / 辨识锚点 / 四维要素 / 硬禁忌 / 正例 / 反例 / 冲突仲裁 / 置信度信号 / 局限 / 与其他包的边界。

**反例比正例重要。** 每条反例都写成「长得像正例、只差一步」，不写稻草人。

## 路由怎么用

五个包不可能每次全扫。调度靠 `references/router.md`：

1. **场合**定主判包（葬礼/面试强制 `CM`，户外强制 `DT`）
2. **单品**定归属（按序判断，命中即停）
3. 两者不一致 → 走三层仲裁

三层仲裁里最要紧的是第三层：

> **主判包不改，只让单品降级。** 单品的出路只有两条：不上场，或者压到最外层/最内层。

这一条是整套系统的命门。违反它的唯一表现就是——为了穿某件衣服，把整套的调性改掉。

## 证据等级

全仓库强制三级标注：

- `[物证]` 一手/官方来源（品牌官网、官方档案、杂志原文、法律或标准文本）
- `[推断]` 据物证反推的可操作判据
- `[归纳]` 通行判断，无成文出处

**绝大多数穿搭规则是 `[推断]`。** 所有版型阈值（「裆线以下 8cm」「肩线外扩 2–6cm」「撞色 ≤1 处」）都是从物证反推出的可执行化数字，不是行业标准，别当成实测数据引用。

各包的真实短板写在包内 §⑨ 局限性里，不藏。举例：

- `OM` 老钱包**不是网上蒸馏的**，基于服饰常识与行业共识
- `JM` 包核心原则来自第三方转述，《POPEYE》官网、AH.H 官网、MUJI 官网均未取到
- `AV` 包品牌商品页被反爬，当季 875 的鞋楦差异无法确认，建议线下试穿

## 用法

把 `SKILL.md` 和 `references/` 一起放进 Agent 的 skill 目录，或直接把 `references/system-prompt-v2.md` 当系统提示词塞进配置框。

衣柜档案不随仓库发布。参考 `references/wardrobe-schema.md` 自己建一份，编号固定，之后所有方案都用编号说话。
