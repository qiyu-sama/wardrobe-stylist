# 风格包定义模板

> 一个风格包 = 一套可执行的判断标准，不是一段描述。
> 只有"喜欢什么"的风格包没用；能说清"什么不算、绝不搭什么、冲突时听谁"的才有用。

---

## 一个风格包必须包含的 8 个区块

### ① 定位（一句话）
这个风格到底是什么，不是什么。**先破除最大误解。**

### ② 辨识锚点（3–5 条）
一眼认出它靠什么。每条要能落到可观察的物理特征上，
不能写成"有质感"这种谁都认领的话。

### ③ 核心要素（4 维）
- **颜色**：允许色域 / 主色 / 点缀色 / 禁用色
- **材质**：欢迎 / 禁区
- **版型**：欢迎 / 禁区
- **细节**：欢迎 / 禁区

### ④ 硬禁忌（5–8 条）
触发即判死。写成"不是 X，但 Y"的形式，
因为禁忌往往长得很像正例。

### ⑤ 正例（5–8 条）
真实可穿的具体组合，每条标注为什么成立。

### ⑥ 反例（5–8 条）
看起来像，但已经跨出边界的具体组合。每条标注越界在哪一步。

### ⑦ 冲突仲裁
"用户想要这个风格，但衣柜/单品只符合另一个"时怎么办。
必须给出顺序明确的裁决，不能和稀泥。

### ⑧ 置信度信号
什么情况下可以判「高」/「中」/「低」，
低置信度时问什么。

---

## 边界条件（写风格包时必须量化）

只有形容词的风格包无法执行，以下必须给数字或明确阈值：

| 维度 | 必须量化成 |
|------|-----------|
| 颜色 | 色相范围、明度、饱和度 |
| 材质配比 | 每类材质占比上限 |
| 元素密度 | 功能元素/装饰元素占比上限 |
| 正式度 | 数值区间 |
| logo | 尺寸/位置/可见度 |
| 版型松量 | 贴身/合身/宽松的分界 |

---

## 质量自检

写完一个包，对照这 6 条：

- [ ] 有没有写"什么不属于这个风格"
- [ ] 硬禁忌是否 ≥5 条，且每条都是"像正例的陷阱"
- [ ] 正例和反例是否只差一步（如果差很远，反例就是稻草人）
- [ ] 冲突仲裁是否有明确优先级，而不是"视情况"
- [ ] 是否给了量化的边界，而不是只有形容词
- [ ] 是否承认了这个风格的局限
